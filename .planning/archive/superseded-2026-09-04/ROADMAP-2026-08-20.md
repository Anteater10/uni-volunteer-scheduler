## New work this session found

Report-only by decision — **nothing below was fixed.** See
`docs/security-review-frontend-infra.md` for the full findings.

| # | Sev | Item | Note |
|---|---|---|---|
| **F1** | HIGH | Both tokens in `localStorage` (`authStorage.js:12,17,30,35`) | Access 60min, **refresh 14 days**. Mitigated but not closed by refresh-token families + reuse detection (migration `0040`). Real fix is httpOnly cookies — that is a backend + frontend change, not a one-liner. |
| **F2** | HIGH | `Caddyfile:36` sets HSTS only | No CSP, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`. **Compounds F1** — with no `connect-src`, nothing stops exfiltration of the tokens in F1. Cheapest high-value fix on this list. |
| **F3** | MED | `react-router-dom` 7.14.0 in vulnerable range | 4 of 5 advisories are RSC/SSR-only and unreachable in a Vite SPA. Only open-redirect-via-protocol-relative-URL plausibly applies. Bump anyway. |
| **F4** | LOW | `frontend/Dockerfile` has no `USER` | Inconsistent with `backend/Dockerfile:54`. |
| **F5** | LOW | `celery_app.py:763,875` log raw magic-link tokens | Correctly gated behind `debug`. Deploy trap, not a defect. |

**Also new, and not in any prior plan:**

- **T1 — Dependabot + Semgrep CE in CI.** ~30 min. Dependabot would have caught
  F3; Semgrep would have caught F1 *and* would catch it again if reintroduced.
  This is the permanent regression net; the manual reviews are not.
- **T2 — OWASP ZAP once against the deployed URL**, during W6. Would have caught
  F2. Not a CI job — a one-time pass on a live environment.
- **T3 — Frontend/backend role-map cross-check.** The `App.jsx` admin-only inner
  block must match the backend's 43 `require_admin` endpoints. A page gated
  `organizer|admin` that calls an admin-only endpoint is a broken screen, not a
  security hole — but it is a broken screen nobody has looked for. ~1 hour.
